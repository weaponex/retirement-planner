# Drift report: EGM README contracts (2026-11-19)

Scope: the seven contract files written or updated by `egm-bootstrap` on 2026-11-19, checked
against the source at `stage-1` (`7cdb0e7`). Every source file in `src/` and `tools/` was read in
full. Only the differences are listed. Items fixed in the README contracts the same day are marked
**Fixed**; the rest are still open.

## README.md

- **Fixed:** the System Overview said the config bundle is "generated at build time".
  `src/engine/config/bundle.ts` is a committed file generated by `npm run config:bundle`
  (`tools/configBundle.ts`); the build only imports it. The wording now says so.
- **Fixed:** "Status: stage 0 (project setup)" was out of date: `stage-1` (tax for one person) is tagged.
- **Fixed:** the intro said version 1 models "variable market returns". The design's 2026-11-18 revision moved
  to fixed returns, and `src/engine/config/keys.ts` says "Returns are fixed (no volatility or
  correlation)".
- **Fixed in the README; still open in the admin guide (SR1-M10):** the Config section said values are "fetched from official sources each January by two
  independent AI sessions". The design's 2026-11-19 revision dropped the yearly refresh
  (Alternative Z, SR1-M10), and only `federal.json` and `ontario.json` are fetched twice;
  `docs/admin-config-guide.md` has the same "each January" wording.
- **Fixed:** the Reference machine section named a "5-second recalculation target". The design's
  Verification Plan sets results within 1 second and tips within 2 seconds of the last edit.
- **Fixed:** the Checks section omitted `npm run build`, which the design's Verification Plan requires.

## src/engine/README.md

- **Fixed:** `types.ts` has no validation ranges. The design's Data contracts give ranges for many
  `PlanInputs` fields (for example `birthYear [1930..2000]`, `survivorPct [40..100]`). The README
  doesn't say where they are enforced (planned for `src/state/persistence/planSchema.ts`, stage 7).

## src/engine/config/README.md

- **Fixed in the README; the schemas are still missing in code:** `objectSchemas` (`schema.ts`) has schemas for four of the eight `object` keys only. The other
  four, `planning.mixes`, `planning.fee_levels`, `planning.spending_phases` and
  `planning.planner_search` (`keys.ts`), have none. While they are `unfetched` this passes, but
  once one gets a value, `checkEntry` returns "no schema for object value" and `config:check`
  fails. The README lists the four schemas but doesn't say the other four are missing (they wait
  on O24, O25, O27 and O31).
- **Fixed in the README; the code follows in stages 2 and 4:** `configStatus(config, today)` (`load.ts`) differs from the design's Config contract, which
  gives `configStatus(config, overrides, today)` and an `overriddenKeys` list. Rule overrides are
  stage 2 work (SR1-M9). `configDefaults()` (design file 24, stage 4) doesn't exist yet. The README
  describes the code as it is and doesn't mention either gap.
- **Fixed:** the `presetColumn` enum in `schema.ts` uses `global_equity`, which is no longer an asset class in
  `ASSET_CLASSES`. A code comment explains it (the presets have three columns), but the README
  doesn't mention it, so readers may take it for a leftover.

## src/engine/jurisdiction/README.md

- **Fixed:** the Invariants say no Ontario rule appears outside `ontario.ts`, and Ontario's age amount
  "reuses" `ageAmount` with its own keys. But `ageAmount` (`federal.ts`) always reads the minimum
  age from `federal.credits.age.min_age`, so Ontario's age amount depends on a federal key. There is
  no Ontario key for it. The README should say this.
- **Open (design, not README):** `Jurisdiction` (`types.ts`) has only `id` and `provincialTax`. The design's file 27 also lists
  `probate`, `lifLimits` and `unlockShare`. The README notes they're planned; the design isn't
  updated to say they arrive in stages 2 and 3.

## tools/README.md

- **Fixed:** Side Effects listed `configBundle.ts` as writing `bundle.ts` and logging. It also reads
  `config/CURRENT_YEAR` and lists `config/<year>/` (through `currentYear` and `configFiles` in
  `lib.ts`), which the README credits only to the other scripts.
- **Fixed:** `configCheck.ts` also prints an "out of date" line when the current year is later than the config
  year. The README mentions the dependency on the date, but not this output.
