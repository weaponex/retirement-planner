# Retirement Planner

A free retirement planner for Canadians that runs entirely in your browser. Version 1 models an
Ontario couple: spending, tax-aware investing and withdrawals, with steady (fixed) returns for each
asset class, both deaths, and threshold warnings.

> **This tool shows projections under the assumptions you enter. It is not financial, tax or
> legal advice.**

**Status:** stage 1 (tax for one person) is done. The app is not usable yet. See the
[design](docs/designs/retirement-planner.md).

## System Overview

A static browser app (Vite, React, TypeScript). The calculation engine in `src/engine` is pure
TypeScript, with no screen or store code. It reads every rule value from `config/<year>/` through
`src/engine/config/bundle.ts`, a committed file generated by `npm run config:bundle` that imports
the JSON statically, and computes in future dollars. The `tools/` scripts generate
that bundle and check the config files against the key list. Agent rules are in
[AGENTS.md](AGENTS.md).

## Subdirectories & System Boundaries

- `src`: [./src/README.md](./src/README.md). The app's browser entry point (a placeholder until
  stage 5) and the engine.
  - `src/engine`: [./src/engine/README.md](./src/engine/README.md). Engine settings
    (`constants.ts`) and data contracts (`types.ts`, including `YearContext` and
    `TaxableIncome`).
  - `src/engine/config`: [./src/engine/config/README.md](./src/engine/config/README.md). The
    key list (`KEY_SPECS`, `ALL_KEYS`), the zod schema (`checkEntry`), the loader
    (`loadConfig`, `configStatus`), and typed, indexed reads (`plain`, `amount`, `list`,
    `brackets`, `phaseIn`). `bundle.ts` is generated.
  - `src/engine/jurisdiction`:
    [./src/engine/jurisdiction/README.md](./src/engine/jurisdiction/README.md). Federal tax
    (`incomeTotals`, `federalTax`), the `Jurisdiction` interface, and Ontario (`ontario`,
    `ontarioTaxParts`), following Form ON428.
  - `src/engine/tax`: [./src/engine/tax/README.md](./src/engine/tax/README.md).
    `personalTax` (federal + provincial + clawback) and the table arithmetic (`bracketTax`,
    `phaseInAmount`, `lowestRate`).
- `tools`: [./tools/README.md](./tools/README.md). Command-line config scripts: `config:bundle`
  writes `src/engine/config/bundle.ts`, `config:check` validates the current year, and
  `config:compare` diffs two fetch candidates.
- Not code, so no contract file: `config/` (rule values and `SOURCES.md`), `docs/` (the design,
  conventions, reviews and history), and `tests/` (unit tests and `tests/fixtures/`).

## Global Invariants

- `[AGENTS.md Values]` No rule value appears in code. Rule values come from `config/`, and engine
  settings from `src/engine/constants.ts`.
- `[src/engine/config/keys.ts header, tools/configCheck.ts]` The key list in `keys.ts` must
  match `config/SOURCES.md` and the design's Config contract. `npm run config:check` fails
  otherwise.
- `[src/engine/config/read.ts:entryOf]` A missing or unfetched rule value throws
  `MissingRuleValueError`. There are no silent defaults.
- `[src/engine/types.ts header]` `…Today` fields are today's dollars and `…Nom` fields are future
  dollars. The engine works in future dollars only.
- `[eslint.config.js]` `src/engine` must not import from `ui/` or `state/`.
- `[AGENTS.md Protected files]` Validated config entries and existing `tests/fixtures/` files are
  never modified by agents.
- `[src/engine/config/bundle.ts header]` `bundle.ts` is generated. Regenerate it with
  `npm run config:bundle`; never edit it by hand.

## Global Side Effects

- `[tools/configBundle.ts]` `npm run config:bundle` overwrites `src/engine/config/bundle.ts`.
- `[tools/lib.ts]` The config tools read `config/CURRENT_YEAR`, `config/<year>/*.json` and
  `config/SOURCES.md` from disk.
- `[src/main.tsx]` The browser entry mounts React into `#root`.
- The engine itself has none: it is made of pure functions, and the config JSON is imported
  statically at build time.

## Config

Every rule value (tax rates, benefit amounts, tables) lives in `config/<year>/`, with its source
and validation status. These are the defaults that ship with the app. Tax and benefit rules are
fetched from official sources by two independent sessions, compared and validated by the admin;
market assumptions are fetched once and spot-checked. Users can change any rule value in Settings,
so a yearly refresh of the defaults is optional. See
[docs/admin-config-guide.md](docs/admin-config-guide.md).

## Personal data

Never commit real household data. `private/` is ignored by git; test with your own numbers by
importing an exported plan file locally.
